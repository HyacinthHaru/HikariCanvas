# 安全与公网部署

HikariCanvas 默认就是安全的：编辑器只监听本机，链接是一次性的。这一页讲清楚它怎么保护你，以及当你确实想让别人远程编辑时，公网部署的正确姿势和必须注意的风险。

## 编辑器是怎么保护的

玩家用 `/canvas confirm` 或 `/canvas open` 打开招牌时，插件在聊天栏给一条带令牌的链接。这条令牌有三重限制：

| 限制 | 说明 |
|---|---|
| 一次性 | 用一次就作废，第二次访问无效 |
| 有时限 | 默认 **15 分钟**内有效，过期作废（可在配置里改） |
| 绑 IP | 绑定第一次访问它的那台机器的 IP，换设备拿同一条链接也进不去 |

令牌**原文不落盘**——它只存在服务器内存里，日志里只记录它的指纹（哈希），泄露日志也无法反推出令牌。

链接失效了不用慌：让玩家重新 `/canvas open <编号>` 就会拿到一条新的。

::: tip
这意味着即使有人在公屏看到了别人的编辑器链接，也基本用不了——要么已经被本人用掉，要么 IP 对不上。
:::

## 默认只在本机，默认安全

插件默认把编辑器服务绑在 `127.0.0.1`（本机回环地址），**外网完全访问不到**。这适用于绝大多数情况：

- 服主自己在服务器主机上操作。
- 玩家在游戏里编辑，编辑器通过本机访问（如单机或局域网）。

只有当你想让玩家**从自己家里的浏览器远程编辑**时，才需要把它开到公网。如果没这个需求，保持默认即可，无需任何额外配置。

## 公网部署的正确姿势

::: danger 不要直接把监听地址改成 0.0.0.0
直接绑 `0.0.0.0` 会让编辑器以**未加密的明文**暴露在公网，令牌可能在传输中被截获。务必走下面的反向代理 + HTTPS 方案。
:::

正确做法是在前面放一层反向代理（nginx 或 Caddy），由它负责对外的 HTTPS，插件本身仍只监听本机：

1. **保持插件监听本机**：`network.host` 维持 `127.0.0.1` 不动。
2. **反代加 TLS**：用 nginx/Caddy 配好你的域名和 HTTPS 证书，把请求转发到插件的本机端口（同时转发 WebSocket 升级）。
3. **登记你的域名**：把对外域名加进 `network.allowed-origins`，否则浏览器连接会被拒绝。

   ```yaml
   network:
     allowed-origins:
       - "https://canvas.example.com"
   ```

4. **改编辑器链接**：把 `network.editor-url` 改成你的 HTTPS 域名，玩家聊天栏拿到的才是可用的公网链接。

   ```yaml
   network:
     editor-url: "https://canvas.example.com/?token={token}"
   ```

详细配置项见[配置](/admin/config)。

## ⚠️ 图片网址上传的内网风险

::: danger 公网开放时务必读这一段
玩家可以用**图片网址**（粘贴一个 URL）来上传图片。插件抓取这个网址时**只校验它是不是 http/https，不再过滤内网地址、回环地址**。

也就是说，一个不可信玩家可以填一个指向你服务器内网的网址（比如内部管理后台、其他服务的地址），借插件去访问那些本不该被外部碰到的内部资源。这在公网实例上是真实的安全风险。

公网开放时，**必须**做到至少一条：

- 用反向代理 / 防火墙把这台服务器和你的内网严格隔离，让它访问不到内部资源。
- 或限制谁能上传（见下方权限），**不要让不可信玩家在公网实例上使用网址上传**。

本机默认部署（只有可信的人能访问）不受此影响。
:::

控制谁能上传：图片上传需要 `canvas.upload` 权限。在公网实例上，建议收紧这个权限，只发给可信玩家。

## 配额：防滥用的安全阀

插件对图片、模板、变量设了一组配额，防止个别玩家把磁盘或内存撑爆。下面是默认值，全部可在[配置](/admin/config)里改：

| 类别 | 限制项 | 默认 |
|---|---|---|
| 图片 | 单张文件大小 | 2 MB |
| 图片 | 单面墙引用图片数 | 16 |
| 图片 | 单人每天上传次数 | 50 |
| 图片 | 全服图片总磁盘 | 1 GB（超出自动清理最旧的） |
| 模板 | 每人可发布模板数 | 20 |
| 变量 | 单人全局变量数 | 500 |
| 变量 | 全服全局变量总数 | 10000 |

配额设为 `0` 表示不限。持有对应豁免权限的玩家可跳过限制（例如 `canvas.upload.bypass-limit`、`canvas.template.bypass-limit`）。

## 审计日志：出事能查

插件会把关键操作记进审计日志，方便你事后排查谁在什么时候做了什么。记录的事件包括：

- 登录认证（成功 / 失败 / 令牌被限流）
- 招牌锁定、解锁、删除、起别名
- 图片上传（成功 / 被拒）
- 权限被拒
- 脚本里"执行命令"积木实际跑了哪条命令
- 后台变量的设置 / 删除等

日志里涉及令牌和 IP 的地方只存哈希指纹，不存原文，既能追溯又不泄露敏感信息。

::: tip
如果你怀疑有人滥用上传或脚本命令，审计日志是第一个该看的地方。
:::
