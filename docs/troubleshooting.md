# 故障排查手册（运维 / 服主向）

**状态：** 0.8.1-SNAPSHOT · 2026-06-22
**适用范围：** 服务器开起来后，玩家或服主遇到「打不开网页 / 画面不刷新 / 字体方块 / 改不了墙 / 上传被拒」等问题时，按本文逐条对照排查。

本文每条都是「**症状 → 原因 → 解决**」三段式，尽量说人话。看不懂某个名词时，姊妹篇有详细背景：

- 部署 / 反代 / TLS：`docs/deployment.md`
- 安全模型 / 权限节点全表：`docs/security.md`
- 渲染为什么游戏内和网页有差别：`docs/rendering.md`
- 协议 / 错误码 / WS 关闭码：`docs/protocol.md`

> 排查总原则：**先看服务器控制台日志**。本插件几乎所有拒绝 / 失败都会在后台打一条 `WARNING` 或 `SEVERE`，写明原因。玩家在网页 / 聊天里看到的提示是脱敏过的简短版，真正的细节在服务器日志里。

## 1. 网页打不开 / 连不上

### 1.1 浏览器打开链接一片空白 / 连接被拒绝

**症状：** 玩家点 `/canvas confirm` 后聊天里弹出的链接，浏览器打开后转圈、报「无法访问此网站」或「连接被拒绝」。

**原因：** 默认监听地址是 `127.0.0.1`（只允许开服那台机器的本机进程连）。玩家若在**另一台机器**上用浏览器访问 `http://127.0.0.1:8877`，那个 `127.0.0.1` 指向的是玩家自己的电脑，而不是服务器。

**解决：**

- **同一台机器开服 + 编辑**：默认就能用，链接里的 `127.0.0.1:8877` 在本机点开即可。
- **局域网内别的机器要编辑**：把 `config.yml` 里的 `network.host` 改成服务器内网 IP（如 `192.168.x.x`），`editor-url` 也跟着改，然后**重启服务器**（host/port 是启动期绑定，`/canvas reload config` 不重绑端口）。
- **公网玩家要编辑**：**不要**直接把 `host` 改成 `0.0.0.0` 暴露到公网（token 走明文，会被嗅探）。必须走 nginx / Caddy 反向代理 + TLS，详见 `docs/deployment.md §3`。

相关配置（`config.yml`）：

```yaml
network:
  host: "127.0.0.1"   # [需重启] 监听地址
  port: 8877          # [需重启] 监听端口
  editor-url: "http://{host}:{port}/?token={token}"
```

### 1.2 端口被占用 / 服务起不来

**症状：** 服务器启动时日志报端口绑定失败，或网页死活连不上。

**原因：** `8877` 端口被别的程序占了，或被防火墙挡了。

**解决：**

- 改 `network.port` 为一个没被占用的端口，**重启服务器**。
- 公网部署时确认反代到 `127.0.0.1:8877` 的转发配置和后端端口一致。
- 检查服务器防火墙 / 安全组放行了对外端口（通常是反代的 443，不是 8877 本身）。

### 1.3 网页里提示连接失败 / 一会儿就断（WS 关闭码 4001）

**症状：** 网页能打开，但很快提示连接断开；服务器日志看到 `WS auth timeout (5s) → close 4001`。

**原因：** WebSocket 连上后必须在 `ws-auth-timeout-seconds`（默认 5 秒）内完成认证（首帧带 token）。超时没认证的连接会被主动断开，关闭码 `4001`。这通常是 token 已过期、链接被重复打开、或网络太慢导致认证帧没及时送达。

**解决：**

- 让玩家**重新跑一次 `/canvas confirm` 或 `/canvas open <id>`** 拿一个新链接（token 有 15 分钟 TTL，且一次性使用，打开过一次就作废）。
- 网络确实慢时可适当调大 `network.ws-auth-timeout-seconds`（范围 1–60），改完重启。
- 如果是反代环境，确认反代正确转发了 WebSocket 升级请求（`Upgrade` / `Connection` 头），否则认证帧根本到不了后端。

### 1.4 公网 / 反代下网页连不上，日志报 Origin 被拒（403）

**症状：** 通过域名访问时网页报错连不上，服务器日志出现 `WS upgrade rejected: Origin=... not in allowlist`。

**原因：** WebSocket 升级有 Origin 白名单防跨站攻击。默认只放行三类：①没有 Origin（非浏览器 / 同源请求）；②`127.0.0.1:端口` / `localhost:端口`；③与 `network.host:port` 完全一致的来源。通过反代域名访问时，浏览器带的 Origin 是你的域名，不在默认白名单里。

**解决：** 把你的对外域名加进 `config.yml`，然后重启：

```yaml
network:
  allowed-origins:
    - "https://canvas.example.com"
```

注意要写完整的 `scheme://host[:port]`，大小写敏感，必须和浏览器实际发送的 Origin 一字不差。

### 1.5 网页提示版本不匹配（WS 关闭码 4002）

**症状：** 网页连上后立刻提示版本不匹配 / 需要刷新；日志里出现 `client_v=... not in [...]`，关闭码 `4002`。

**原因：** 前端代码和后端的协议版本对不上（后端只接受 `SUPPORTED_MIN..SUPPORTED_MAX` 范围内的版本，当前为 7..7）。一般是升级了 jar 但浏览器缓存了旧前端，或者前端产物没跟着 jar 一起更新。

**解决：**

- 让玩家**强制刷新浏览器**（清缓存 / 无痕窗口）。
- 确认部署的是同一次构建出来的产物：前端打进了 shadow jar，所以**换 jar 时不要混用旧前端缓存**。
- 自建前端 / 反代缓存了静态资源的，清一下反代缓存。

### 1.6 频繁重试后被限流（WS 关闭码 4429）

**症状：** 某个 IP 反复连接被断开，关闭码 `4429`，日志 `WS auth rate limited`。

**原因：** 防 token 暴力枚举：每个 IP 每分钟最多尝试 `security.token-rate-limit.per-minute`（默认 10）次 token 校验，超了就断开并记审计 `TOKEN_RATE_LIMIT_EXCEEDED`。正常玩家不会一分钟试十几次。

**解决：**

- 正常情况这是在保护你，等一分钟即可恢复。
- 如果是合法玩家因为不断刷新页面触发，让他停下来，用一个**新链接**打开一次就好，别反复点。
- 确有需要可调 `security.token-rate-limit.per-minute`（下界 1），改完重启。

## 2. 游戏内画面不刷新 / 不显示

### 2.1 重启服务器后墙是空白 / 占位图

**症状：** 服务器重启后，原本有画的墙变成空白或占位图案。

**原因：** 启动时插件会跑一次「墙恢复」（WallRestorer），把数据库里每面墙的内容重新画回对应地图。某面墙恢复失败时（地图被破坏、世界没加载、IO 出错），它会画占位并在日志里记 `SEVERE: wall restore ...`。恢复失败的墙数据**不会被删**，下次重启会重试。

**解决：**

- 看日志确认是哪面墙、什么原因失败。常见是该墙所在的**世界还没加载完**或被卸载了。
- 多世界服务器要确认墙所在的世界正常加载。
- 玩家与恢复失败的墙交互时会看到「该墙启动时恢复失败，请看服务器日志」之类提示，按日志原因处理。

### 2.2 编辑时网页改了，但游戏里地图不动 / 几秒后才动

**症状：** 网页里拖动元素很流畅，但站在墙前看到的地图更新有延迟，或停手后就不刷了。

**原因：这是预期行为，不是 bug。** 帧率策略是：玩家停手 → 0 fps（不刷）；持续编辑 → 上限 `throttle.projection-fps`（默认 5 fps）。这样设计是为了控制发给客户端的地图数据包量。Minecraft 原生地图同步本身也有 250ms–5s 的抖动。

**解决：**

- 停手后地图停在最后一帧是正常的，没必要持续刷。
- 想让动态内容（变量 / 时间轴 / 脚本补间）刷得更勤，调 `rendering.adaptive-fps` 段（`high-freq-min-interval-ms`）和 `throttle.projection-fps`。注意这会增加 CPU 和带宽，按「工具不替你做成本估算」的设计，系统不会自动降级，配多高是服主的决定。

### 2.3 站在墙前看不到任何更新（要走近才刷）

**症状：** 在远处看墙没变化，走近才看到最新内容。

**原因：** 服务端只给「能看到这块地图（区块已加载到客户端）的观察者」推送更新。没人看的地图不会白白渲染和发包（viewer-gated，省资源）。

**解决：** 这是预期的省资源行为。走进墙的区块加载范围内即可看到最新内容；新观察者进入时会收到一次全量补发。

### 2.4 墙根本没出现 / 物品展示框是空的

**症状：** `/canvas confirm` 之后墙上没有出现地图，或物品展示框是空的。

**原因 / 解决：**

- 确认 `/canvas confirm` 真的成功了（聊天里应回「Wall created ...」并给出编辑器链接）。失败会提示具体原因（选区不合法、墙被占用、地图池耗尽等）。
- 看到 `Pool exhausted`：地图池满了。每面墙借出的地图会一直占着直到 `/canvas delete`。调大 `map-pool.max` / `map-pool.initial` 并重启，或删掉不用的墙释放地图。
- 多世界服务器：地图按世界分桶，墙和它用的地图必须在同一世界。跨世界绑定会失败。可用 `map-pool.per-world` 给每个世界单独预热地图数。

## 3. 字体不显示 / 显示成方块

### 3.1 某些字（尤其中文 / 特殊符号）显示成方块或空白

**症状：** 文字元素里部分字符显示成「□」或干脆不显示，游戏内和网页都一样。

**原因：** 选用的字体里没有这个字符（缺字）。内置 22 枚字体各有覆盖范围，西文装饰体（如 Lobster / Bangers）基本不含中文。

**解决：**

- 中文请选中文字体：`source_han_sans`（黑体）/ `source_han_serif`（宋体）/ `ark_pixel`（像素）/ 各艺术体（得意黑、马善政楷书等）。
- 真的缺这枚字体覆盖不到的字时，放一个覆盖更全的字体进用户字体目录（见下一条）。

### 3.2 内置字体全都不显示 / 启动日志报字体缺失

**症状：** 所有文字都渲染不出来，启动日志出现 `built-in font missing from classpath: ...；确认 ./gradlew downloadFonts 已跑过`，或 `did ./gradlew generatePalette run?`。

**原因：** 字体是构建期由 Gradle `downloadFonts` 任务下载后打进 jar 的，仓库本身不含字体文件。如果你拿到的 jar 构建不完整（字体没下载成功就打包了），jar 里就缺字体。

**解决：**

- 用官方 Release 的 jar，或自己构建时确认 `downloadFonts` 跑成功（见 §7.1）。
- 缺字体时插件不会崩，会 fallback 到还存在的字体；连默认字体都没有时才会完全画不出文字——这种情况基本只会出现在构建坏掉的 jar 上。

### 3.3 我放了自定义字体，但网页字体下拉里没有 / 用不了

**症状：** 把 `.ttf` / `.otf` 丢进字体目录，但编辑器里选不到。

**原因 / 解决：**

- 用户字体放在 **`plugins/HikariCanvas/fonts/`** 目录（`.ttf` 或 `.otf`），**放完要重启服务器**才会扫描加载（启动期一次性扫描）。
- 文件名（去掉扩展名）就是字体 id，**必须只含 `a-z A-Z 0-9 _ -`**。带点、空格、中文、隐藏文件（如 `.x.ttf`）的会被跳过并在日志里记 `skipping external font with invalid id ...`。把文件改名即可。
- 同名会覆盖内置字体（文件名 id 一样时）。

### 3.4 自定义字体加载后，前几秒文字宽度 / 换行有点怪

**症状：** 刚启动那几秒，用户字体的文字换行位置 / 间距略有偏差，之后恢复正常。

**原因：这是预期行为。** 用户字体没有构建期预生成的字宽表（metrics），启动后由后台线程现算（每枚字体约 1–2 秒）。算好之前，宽度按近似值（ASCII≈半角、CJK≈全角）兜底，所以前几秒可能略有偏差。

**解决：** 等几秒让后台算完即可，无需操作。这样设计是为了不让 N 枚用户字体在启动时阻塞主线程。

### 3.5 图标显示不出来 / 自定义图标用不了

**症状：** 图标元素显示占位，或自定义 SVG 图标在编辑器里找不到。

**原因 / 解决：**

- 内置图标（Font Awesome Free）打在 jar 里，正常无需操作。
- 用户自定义图标放 **`plugins/HikariCanvas/icons/`**，文件为 `<id>.svg`，文件名（去 `.svg`）须匹配 `[a-z0-9_-]+`，注册为 `user/<id>`。**放完要重启服务器**。

## 4. 游戏内与网页预览不一致

### 4.1 网页里清晰的边缘 / 渐变，到游戏里变粗糙 / 有色块

**症状：** 网页预览很顺滑，游戏里地图上看起来颜色被「凑近」了、边缘有锯齿、渐变有色阶。

**原因：这是预期行为，无法消除，也不是 bug。** Minecraft 地图只有固定的 248 色调色板，且不支持中间透明度。插件渲染时：

- **强制关闭抗锯齿**（双端都关），否则两端的抗锯齿算法不同会导致游戏内和网页对不上——宁可两端都「硬边」也要保证一致。
- **把每个像素量化到最接近的调色板颜色**（32³ Lab 查找表）。所以网页里的精确颜色，到游戏里会落到某个最接近的可用颜色上。
- 渐变 / 柔和过渡通过 **Bayer 4×4 抖动**（dither）来模拟连续色阶，凑近看会看到点阵图案。

**解决：** 没法让 MC 地图显示出 248 色之外的颜色，这是平台限制。要让过渡更自然就开元素的「柔和过渡」（dither）模式。两端的差异是受控且一致的——两台不同机器上看同一面墙应该是一样的。

### 4.2 半透明颜色在游戏里变成不透明的近似色

**症状：** 设了 50% 透明度的颜色，游戏里显示成一个不透明的相近颜色。

**原因：这是预期行为。** MC 地图不支持中间透明度。半透明元素会先和它下面的内容合成出一个实色，再量化到调色板。只有「整块透明背景」（alpha 很低）才会在地图上真正透明，中间透明度会被合成成实色。

**解决：** 想要真透明背景用画布设置里的「设为透明背景」。想要某种半透明叠加效果，请理解最终落地的是合成后的实色。

## 5. 锁定的墙改不了

### 5.1 打开墙后所有编辑控件都是灰的 / 拖不动 / 删不掉

**症状：** 打开某面墙后，右侧面板控件禁用、元素拖不动、快捷键失效。

**原因：这是「锁定」状态，是预期的。** 墙的作者可以把自己的墙「只读冻结」防误改。锁定由**网页编辑器顶栏的 Lock 按钮**控制，**不是游戏命令**（`/canvas publish` / `/canvas unpublish` 早已废弃）。

**解决：**

- 你是这面墙的作者（owner）：网页顶栏点 Lock 按钮解锁即可。只有作者才看得到解锁按钮。
- 你不是作者：你无法解锁别人的墙。需要管理员用 `canvas.admin.bypass-lock` 权限打开。
- 想找谁是作者：墙的 owner 信息按创建者记录，管理员可查。

### 5.2 别人打不开我锁定的墙

**症状：** 把墙锁定后，别的玩家 `/canvas open` 提示墙被锁定（Forbidden）。

**原因：这是预期的。** 锁定后非作者无法打开（除非持 `canvas.admin.bypass-lock`）。未锁定的草稿墙默认任何有 `canvas.edit` 的玩家都能打开（协作中间态）。

**解决：** 要让别人编辑就别锁定；要保护就锁定。管理员可用 bypass 权限介入。

## 6. 图片 / SVG 上传被拒

### 6.1 上传图片提示被拒（UPLOAD_REJECTED / 413 / 415 / 429）

**症状：** 拖图 / 粘贴图 / 贴 URL 上传时报错。

**原因 + 解决：** 上传有多层校验，对照 `config.yml` 的 `images` 段：

| 现象 | 原因 | 解决 |
|---|---|---|
| 413，提示太大 | 超过 `max-size-kb`（默认 2048 KiB） | 压缩图片，或调大 `max-size-kb` |
| 415，类型不对 | 不是允许的格式，或文件头和声明的类型对不上（防伪造） | 只传 `allowed-mime` 列的：PNG / JPEG / WebP |
| 提示这面墙图片太多 | 超过 `max-per-wall`（默认 16） | 删掉墙上的旧图，或调大上限 / 给 `canvas.upload.bypass-limit` |
| 429，今天传太多 | 超过 `max-uploads-per-day`（默认 50） | 等明天，或调大 / 给 bypass 权限 |
| 磁盘配额相关 | 全服上传总量超 `max-total-storage-mb`（默认 1024 MiB），会触发 LRU 自动清理最旧的 | 调大配额或清理 |
| 解码超时被拒 | 图片解码超时（防压缩炸弹），有 200ms 隔离解码限制 | 换一张正常的图片 |
| URL 上传失败（502/504） | 远程地址拉不到 / 超时 / SSRF 防御拦截 | 换一个公网可达的直链图片地址 |

需要某些玩家不受上传配额限制时，给他们 `canvas.upload.bypass-limit` 权限（默认仅 op）。

### 6.2 SVG 导入被拒（SVG_TOO_LARGE / SVG_TOO_COMPLEX / SVG_HAS_ENTITY）

**症状：** 在编辑器里导入 SVG 时报错。

**原因 + 解决：** SVG 导入在前端做安全校验：

| 错误码 | 原因 | 解决 |
|---|---|---|
| `SVG_TOO_LARGE` | SVG 文本体积超上限 | 精简 SVG（删冗余、降精度） |
| `SVG_TOO_COMPLEX` | 形状数超上限（默认 500）或估算总顶点数超上限 | 简化图形、合并路径、减少节点 |
| `SVG_HAS_ENTITY` | SVG 里含 `DOCTYPE` / `ENTITY`（XXE 攻击面），一律拒绝 | 用工具导出干净的 SVG，去掉 DOCTYPE / 实体声明 |

### 6.3 导入 .canvas 工程文件被拒（IMPORT_*）

**症状：** 导入 `.canvas` 工程包失败。

**原因 + 解决：** 工程导入有防大文件 / zip 炸弹的限额，对照 `config.yml` 的 `import` 段：

| 错误码 | HTTP | 原因 | 解决 |
|---|---|---|---|
| `IMPORT_ZIP_TOO_LARGE` | 413 | 整包超过 `canvas-max-mb`（默认 10 MB），或解压总和超 `canvas-max-total-mb`（默认 50 MB），或单文件超 `canvas-max-entry-mb`（默认 10 MB） | 减小工程体积或调大对应上限 |
| `IMPORT_SPEC_UNSUPPORTED` / `IMPORT_SIZE_MISMATCH` | 409 | 工程格式版本不支持，或声明大小与实际不符 | 用同版本插件导出的工程；别手改包 |
| `IMPORT_BAD_ENTRY` / `IMPORT_MALFORMED` | 400 | 包内文件结构损坏 / 无法解析 | 重新导出工程 |

## 7. `/canvas reload config` 不生效

### 7.1 改了 config 跑了 reload，但没变化

**症状：** 改了 `config.yml`，跑 `/canvas reload config`（需 `canvas.admin`）后某些配置没生效。

**原因：部分配置是启动期一次性注入的，热重载改不了。** 最典型的是 `network.host` / `network.port`——socket 已经绑死，reload 只会刷新引用 + 打印配置，不会重绑端口。reload 后命令本身也会提示「host/port changes require server restart」。

**解决：**

- 标了 **`[需重启]`** 的项（host / port 等）改完**必须重启服务器**。
- 大多数其他项（帧率、限流、配额、脚本预算、命令模板白名单等）`/canvas reload config` 即可热更。`/canvas reload templates` 单独重载模板。
- 改完看一眼 reload 命令回显的配置摘要，确认读进去的是你期望的值。

## 8. 构建 / 部署期问题

### 8.1 构建时字体下载慢或失败

**症状：** `./gradlew downloadFonts`（或 `syncFontsToWeb`）卡很久或报错；首次构建尤其慢。

**原因：** 字体不入仓库，构建期从网络抓取（几十 MB），并做 SHA-256 校验。网络不稳就慢 / 失败。

**解决：**

- 任务**内置了重试**（日志会打 `[retry N/M] ...`），偶发失败可直接重跑 `./gradlew downloadFonts`。
- 报 `SHA-256 不符`：说明下载的文件和 pin 的校验值对不上（被镜像改写 / 下载损坏 / 上游变更）。重下；若是上游确实换了文件需更新 pin。
- 图标同理（`downloadIcons`，也有 SHA-256 校验 + 重试）。
- 首次构建建议在网络好的环境跑，产物会缓存到 `build/downloaded-fonts/`，后续构建不重复下载。

### 8.2 shadow jar 体积很大（150+ MB）

**症状：** 打出来的 `HikariCanvas-x.y.z-SNAPSHOT.jar` 有 150 多 MB，怀疑不正常。

**原因：这是正常的。** jar 里打包了 22 枚字体（含思源黑体 / 宋体这类大字库）、Font Awesome 图标库、以及整个前端编辑器产物。这些都是运行时必需的——字体走 jar 内置加载，前端由后端直接提供。

**解决：** 不用处理。体积大主要来自字体。这是设计取舍（开箱即用，不让服主自己凑字体）。

## 9. 升级注意（别乱换运行环境）

**症状：** 想升级 Java / Paper 来「跟上最新版」。

**原因：插件锁定了运行环境，乱换会崩。** 几条硬纪律：

- **Java 21**：锁死，**不要升到 Java 25**。守住 1.21 LTS 生态。
- **Paper 1.21.x**：**不要升到 Paper 26.x**。Paper 26.1 起移除了插件的服务端重映射，任何碰底层的插件在 26.x 上会崩。本插件的架构已经为「未来只改版本号、不动代码」做了准备，但**前提是你别跨到 26.x**。
- 公网部署务必反代 + TLS（见 §1.1 / §1.4 和 `docs/deployment.md`），别图省事直绑公网。

**解决：** 想升级先确认目标版本仍是 Java 21 + Paper 1.21.x。跨大版本前等插件官方明确支持。

## 10. 语言 / 文案问题

### 10.1 玩家看到的语言不是预期的

**症状：** 玩家收到的命令回复 / wand 提示是英文，但他希望看中文（或反过来）。

**原因：** 插件按**各玩家自己的 Minecraft 客户端语言**自动选文案（内置 `en_us` / `zh_cn`）。客户端语言设成什么，插件就用什么；没有对应语言文件时，回落到 `config.yml` 里 `i18n.default-locale`（默认 `en_us`）。

**解决：**

- **让玩家改自己的客户端语言**：玩家进游戏设置 → 语言 → 改成对应语言，下次命令就切过去了。
- **想让所有玩家统一看某种语言**：在 `config.yml` 里把 `i18n.default-locale` 改成目标语言 ID（如 `zh_cn`），然后 `/canvas reload config` 热重载，不需要重启服务器。注意：这只影响客户端语言没有对应文件的玩家；已有对应文件的玩家还是看自己语言。如果要彻底统一，把其他语言的 lang 文件改成同样内容，或直接删掉。

```yaml
# config.yml（改完 /canvas reload config 即可）
i18n:
  default-locale: zh_cn
```

### 10.2 改了 lang 文件（或 default-locale），但没生效

**症状：** 编辑了 `plugins/HikariCanvas/lang/zh_cn.yml`（或改了 `config.yml` 里的 `i18n.default-locale`），玩家还是看到旧文案。

**原因：** 语言文件在内存里有缓存，文件改了之后要主动触发重载。

**解决：** 跑 `/canvas reload config`（需 `canvas.admin`），lang 目录下所有文件会被立即重新读入，`default-locale` 也跟着生效。不需要重启服务器。

### 10.3 加了新语言文件但插件没认出来

**症状：** 在 `plugins/HikariCanvas/lang/` 放了一个新 `fr_fr.yml`，法语客户端玩家还是看到 `en_us` 的文案。

**原因 / 解决：**

- 确认文件名和 Minecraft 的语言 ID **完全一致**（如 `fr_fr.yml`，不能用大写或连字符 `fr-FR.yml`）。
- 文件放好后跑 `/canvas reload config` 重载，不用重启。
- reload 后如果日志里出现 `[i18n] failed to load fr_fr.yml: ...`，说明文件有 YAML 语法错误，按日志信息修。
- 某条 key 翻译缺失时，插件会自动回落到 `default-locale` 对应语言（不会崩），同时在日志里打一条 `[i18n] missing key: ...` 方便你补全。
