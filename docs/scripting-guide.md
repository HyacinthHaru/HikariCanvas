# HikariCanvas 积木脚本使用指南

让招牌「有事发生就自动做点什么」——有人进服就广播、列车到点就闪一下、玩家靠近就播声音、
比分变了就改文字。全靠拖积木，不写代码。

> 这是**给玩家 / 服主看的大白话教程**。想看内部设计（数据结构 / 执行引擎 / 协议）去
> `docs/scripting.md`（设计总纲）。
>
> 姊妹篇：[时间轴动画使用指南](timeline-guide.md)（让元素随时间自己动）、
> [变量系统使用指南](variables.md)（动态数据从哪来）。

---

## 第一部分：做你的第一条脚本规则

### 1.1 脚本是什么

一句话：**有事发生 → 自动做点什么。**

普通招牌是死的，你写好它就一直那样。脚本让招牌「活」起来：你定一个**触发条件**（比如「有玩家进服」），
再排一串**要做的事**（比如「播一段欢迎动画」「在聊天框发条消息」），保存以后游戏里一旦满足条件就自动跑。

每条规则就是：**一顶帽子**（什么时候开始）+ **一串积木**（依次要做的事）。一面招牌可以挂很多条规则。

### 1.2 打开积木编辑器

编辑器顶部点 **拼图图标**（🧩）→ 弹出**全屏积木画布**。

画面分几块：

- **左上角是规则列表** —— 这面招牌已有的规则都在这。点「新建规则」加一条新的。
- **中间一大片是积木画布** —— 可以拖动平移、滚轮缩放（地方不够就拖远点）。规则的积木都拼在这。
- **左边是积木库** —— 按类别分组（触发 / 元素动作 / 动作 / 控制 / 时间轴 / 命令），把积木拖到画布上用。
- **右上角有「试跑 / 关闭」** —— 试跑会当场执行一遍，关闭退出编辑器。
- 改动**自动保存**，没有「保存」按钮。规则有没填完的地方会标 `⚠ N 处待完善`，修好才会自动存。

### 1.3 帽子积木 = 什么时候开始

每条规则最上面是一顶**帽子**（橙色），它决定「这条规则什么时候触发」。新建规则会自带一顶帽子，
点帽子上的「什么时候触发」下拉就能换触发方式（进服 / 定时 / 玩家靠近……，全部见[第二部分](#第二部分所有触发器)）。

帽子下面接的积木，就是触发后**从上往下依次执行**的事。

### 1.4 拖动作积木

从左边积木库拖一块到帽子下面，吸上去就接成一串。常见的几块：

- **发消息**（在聊天框 / 动作栏 / 标题给玩家发字）
- **元素动作**：移到 / 改大小 / 旋转到 / 改文字 / 改颜色 / 显示 / 隐藏……（直接改招牌上某个元素）
- **播放声音** / **播放粒子**（给附近或全服玩家来点声光）
- **播放时间轴**（触发一段你预先排好的[时间轴动画](timeline-guide.md)）
- **设置变量** / **变量增加**（改一个[变量](variables.md)的值）

每块积木里有要填的格子（选元素、填数值、选声音……），下拉或输入即可。

### 1.5 如果-否则（条件分支）

想「分情况处理」就用 **如果**（绿色，C 形）积木：它有一个**条件**、一个**那么**槽、一个**否则**槽。
条件成立就执行「那么」里的积木，不成立就执行「否则」里的。

条件用可视构建器拼，比如「变量 `user/score` 大于 `10`」。点「加条件」能拼多行，用「且 / 或」连起来；
嫌不够灵活可以切到「高级（写表达式）」自己写，例如：

```
var("user/score") >= 10 && var("user/team") == "red"
```

（条件里怎么引用变量、能比什么，见 [4.3](#43-脚本里用变量)。）

### 1.6 保存 + 试跑

改动自动存。想当场看看效果，点右上角 **试跑**。

> ⚠️ **试跑是真的执行**，不是模拟！它会真的发消息、真的执行命令、真的改招牌、真的播声音。
> 试跑跑完，积木会按执行顺序逐个亮边框（绿 = 执行了 / 黄 = 被拦下 / 红 = 出错了），方便你看哪步出了问题。

规则**有没填完的地方时试跑会被挡住**（先把 `⚠` 提示的问题修好）。

### 1.7 一分钟上手清单

1. 🧩 顶部拼图图标 → 打开积木编辑器
2. 左上「新建规则」→ 自带一顶帽子
3. 点帽子「什么时候触发」下拉 → 选触发方式（比如「当 玩家进服」）
4. 从左边积木库拖一块「发消息」接到帽子下面 → 填上内容
5. 想分情况？拖一块「如果」，设条件，往「那么 / 否则」里塞积木
6. 点右上「试跑」看效果（⚠ 会真执行）
7. 改动自动保存，关掉编辑器，游戏里就生效了

## 第二部分：所有触发器

每条规则只有一顶帽子。下面是全部可选的触发方式。带「需服主开权限」的，普通玩家默认用不了
（见[第五部分](#第五部分服主运维)）。

| 触发器 | 帽子文案 | 什么时候触发 | 要填 |
|---|---|---|---|
| 变量变化 | 当 变量变化 | 你盯的某个[变量](variables.md)一改值就触发 | 选一个变量 |
| 定时器 | 每隔一段时间 | 每隔 N 秒自动触发一次 | 间隔秒数（1~86400） |
| 画板就绪 | 当 画板就绪 | 这面招牌在游戏里加载好的那一刻 | 无 |
| 玩家进服 | 当 玩家进服 | 任何玩家进入服务器时（需服主开权限） | 无 |
| 玩家击杀 | 当 玩家击杀 | 一个玩家被另一个玩家击杀那一下（PvP；摔落 / 岩浆等环境死亡、击杀生物都不算）（需服主开权限） | 无 |
| 玩家靠近 | 当 玩家靠近 | 有玩家走进招牌周围 N 格范围（从外面进来那一下） | 范围格数（1~32） |
| 离开靠近区域 | 当 玩家离开范围 | 有玩家走出招牌周围 N 格范围（从里面出去那一下） | 范围格数（1~32） |
| 右键画板 | 当 右键画板 | 有玩家右键点这面招牌（需服主开权限） | 无 |
| 玩家退服 | 当 玩家退出游戏 | 任何玩家离开服务器时（需服主开权限） | 无 |

典型用法：

- **变量变化** —— 比分板变了就刷新文字；插件推个「告警=真」就让招牌闪。和[时间轴的「变量变了就播」](timeline-guide.md)是一个思路，区别是脚本能再加条件和别的动作。
- **定时器** —— 每 5 秒滚动一次广告语、每分钟刷一次「当前在线人数」。
- **画板就绪** —— 招牌一加载就摆好初始状态（把某元素移到起点、设好默认文字）。
- **玩家进服** —— 全服欢迎横幅、给招牌的欢迎语换上刚进来玩家的名字。
- **玩家击杀** —— 击杀计数 +1、播个胜利音效。
- **玩家靠近 / 离开范围** —— 走近时招牌「亮起来」（变大 / 显示细节），走远时「收起来」。常配合做感应式展示牌。
- **右键画板** —— 把招牌当按钮：点一下切换显示内容、播段动画、给点奖励（配命令模板）。
- **玩家退服** —— 在线人数立刻 -1、记录最后离开时间。

> **关于触发频率**：触发器没有单独的「冷却」设置，系统靠[执行预算](#44-脚本被熔断时budget-上限)兜底——
> 同一条规则每秒最多触发若干次（默认 10），超出的直接丢掉，不会把服务器拖垮。

## 第三部分：所有动作积木

积木库按类别分组（颜色也对应分组）。下面按友好名分类列全。**带「需服主开权限」的默认普通玩家用不了。**

### 3.1 变量类（改一个变量的值）

| 积木 | 做什么 |
|---|---|
| 设置变量 | 把某个变量直接设成一个值（值里可以带 `${var:X}` 引用别的变量） |
| 变量增加 | 把某个数字变量加上 / 减去一个数（增量填负数就是减） |
| 变量乘除 | 把某个数字变量乘以 / 除以一个倍数 |
| 设随机数 | 给变量随机一个 `最小`~`最大` 之间的数（做骰子、抽奖很好用） |
| 变量取整 | 把变量当前数值四舍五入 / 向下取整 / 向上取整 |
| 变量复制 | 把一个变量的当前值原样复制到另一个变量 |
| 文本拼接 | 在某个变量末尾追加一段文字（文字里可带 `${var:X}`） |

### 3.2 元素类（直接改招牌上的某个元素）

这些是「**元素动作**」分组里最直观的一批，每块先选**哪个元素**，再填目标：

| 积木 | 做什么 |
|---|---|
| 移到 | 把元素移到指定的横纵坐标 |
| 移动一点 | 在当前位置基础上**相对**移动一段（横向 / 纵向偏移量） |
| 改大小 | 把元素设成指定的宽 / 高 |
| 旋转到 | 把元素旋转到指定角度（0~359） |
| 设透明度 | 设元素的不透明度（0 = 全透明，1 = 不透明） |
| 显示 | 让元素显示（透明度设 1） |
| 隐藏 | 让元素隐藏（透明度设 0） |
| 改文字 | 改文字元素的内容（可带 `${var:X}` 引用变量） |
| 改颜色 | 改文字元素的颜色（填 `#RRGGBB` 十六进制色） |
| 元素置顶/置底 | 把元素挪到本图层最上层（盖住别的）或最下层 |
| 克隆元素 | 复制一个元素出来，放在原位偏移一点的位置 |
| 删除元素 | 删掉一个元素 |

> 改坐标 / 大小不用手抄数字——有更聪明的办法，见 [4.1 幽灵拖动设目标坐标](#41-幽灵拖动设目标坐标预览框点选当前值)。

### 3.3 时间轴类（触发预排好的动画）

| 积木 | 做什么 |
|---|---|
| 播放时间轴 | 控制一条[时间轴动画](timeline-guide.md)：播放 / 暂停 / 跳到某个时刻 |
| 播放并等待 | 播一条时间轴，**等它播完一轮**再继续往下走（脚本在这一步挂起等待） |

先去[时间轴编辑器](timeline-guide.md)排好动画，这里下拉就能选到它。

### 3.4 补间动画「在 X 秒内」

「**在 X 秒内**」积木（控制类，C 形包裹）让元素**平滑动起来**——不再是瞬间跳到新位置 / 新颜色，
而是用一段时间慢慢过渡。

怎么拼：

1. 拖一块「在 X 秒内」进规则。
2. 设**时长**（毫秒，如 `1500` = 1.5 秒）+ 选**缓动**（匀速 / 由慢到快 / 由快到慢 / 两头慢中间快 / 自定义曲线）。
3. 往它**里面**拖元素动作（移到 / 改大小 / 旋转到 / 设透明度 / 改颜色），选元素 + 目标值。
4. 可以放**多个**，会同时动（边移动边放大边变色）。

触发后：元素在你设的时长内平滑过渡到目标，**过渡完停在目标**（永久）。脚本会**等补间做完**才走下一个动作。

> **只能放属性动作**（移到 / 改大小 / 旋转到 / 设透明度 / 改颜色）。放别的（发消息等）会拖不进去——那些放在补间**外面**。
>
> **和时间轴一起用**：补间和你预排的[时间轴动画](timeline-guide.md)能**同时**在一面招牌上跑（背景时间轴循环 + 脚本触发的滑入），互不打断。
>
> **动画帧率**：积木画布顶部有「动画帧率」（默认 30，可调 1~60）——这面招牌的所有补间用这个帧率。高 = 更顺但更耗性能，按服务器情况调，**每面招牌独立**。

### 3.5 效果类（声光 / 给玩家发消息）

| 积木 | 做什么 | 权限 |
|---|---|---|
| 播放声音 | 给「附近玩家 / 全服玩家」播一个音效（可调音量、音调） | 需服主开权限 |
| 播放粒子 | 在招牌位置播一簇粒子（14 种内置：火焰 / 爱心 / 烟花 / 暴击……可设数量和偏移） | — |
| 发消息 | 给「触发的玩家 / 全服玩家」在聊天框 / 动作栏 / 标题发一条文字 | — |
| 弹出标题 | 给玩家弹一个屏幕中央大标题 + 副标题（可设淡入 / 停留 / 淡出时长） | — |
| 日志 | 往服务器日志 / 控制台输出一行文字（玩家看不到，调试自己脚本时用） | — |

> 「发消息」「弹出标题」里的文字都能带 `${var:X}`，会自动替换成变量当前值。
> 「发给 / 范围」选「全服玩家」就是广播，选「触发的玩家」就只发给触发这条规则的人（比如刚进服 / 刚右键的那位）。

### 3.6 流程控制

| 积木 | 做什么 |
|---|---|
| 如果 | 条件成立走「那么」，否则走「否则」（见 [1.5](#15-如果-否则条件分支)） |
| 随机分支 | 按一个百分比概率，随机走「那么」或「否则」（做随机事件） |
| 等待 | 停顿一段时间（毫秒）再往下走 |
| 等待条件 | 卡在这里等到条件成立（或超时）才往下走 |
| 重复 | 把里面的积木重复执行固定次数（1~100） |
| 重复直到 | 反复执行里面的积木，直到条件成立（带「最多次数」安全阀，防转圈） |
| 停止脚本 | 立刻中止本条规则这一次的执行，后面的积木都不再跑 |

> 「等待」「等待条件」「播放并等待」「在 X 秒内」都会让脚本**挂起**——它不占用线程死等，到点 / 条件满足了自动续上。

### 3.7 执行命令（需服主配白名单）

| 积木 | 做什么 | 权限 |
|---|---|---|
| 执行命令 | 以服务器身份执行一条**服主预先配好的命令模板**（填几个参数） | 需服主开权限 |

这是唯一能「跳出招牌、影响整个服务器」的积木，所以**双重把关**：

1. **服主要先在 config 里写好命令模板**（白名单），没写的命令模板根本执行不了。
2. **玩家要有 `canvas.script.command` 权限**（默认只有管理员）。

服主没配任何模板时，这块积木会**灰显**，提示「服主还没配命令模板」。配置方法见 [5.2](#52-命令模板白名单)。

## 第四部分：进阶

### 4.1 幽灵拖动设目标坐标（预览框点选当前值）

改元素坐标 / 大小时，不用去画布上手抄数字。积木编辑器**右侧有一个当前招牌的预览框**（可折叠 / 拖宽）。

- **点选取当前值**：元素类积木（移到 / 改大小 / 旋转到 / 设透明度）旁边有个**靶心按钮**，点它后再去右侧预览框**点一个元素**——这块积木就自动填好那个元素的 `元素` 字段，并把它**当前的**坐标 / 大小 / 旋转 / 透明度填进目标值。省去手抄。
- **幽灵拖动设目标**：在预览框里**拖一个元素的虚影**到你想要的终点位置（拖中心 = 设目标位置 / 拖角 = 设目标大小 / 转手柄 = 设目标旋转角），积木就记下这个目标坐标。比盯着数字调直观得多。

### 4.2 脚本 + 时间轴一起用

脚本和[时间轴](timeline-guide.md)**不是二选一**，而是配合：

- **时间轴** = 你预先排好的一段动画（关键帧 + 缓动），是「素材」。
- **脚本** = 决定「什么时候播、播之前 / 之后还做什么、满足什么条件才播」，是「编排」。

所以常见组合是：脚本里用「播放时间轴」「播放并等待」积木去触发预排的动画；或者「在 X 秒内」补间和背景循环时间轴同时跑。两套系统在同一面招牌上共存，互不打架。

### 4.3 脚本里用变量

脚本和[变量系统](variables.md)深度打通：

- **引用变量值**：凡是填文字的格子（发消息内容、改文字、设置变量的值、文本拼接……）都能写 `${var:X}`，执行时替换成变量当前值。
- **改变量**：用变量类积木（设置变量 / 变量增加 / 变量乘除 / 设随机数 / 变量取整 / 变量复制 / 文本拼接）。
- **拿变量做条件**：「如果 / 等待条件 / 重复直到」的条件里用 `var("变量名")` 取值来比较，例如：

  ```
  var("user/score") > 0
  var("user/team") == "red"
  var("user/count") >= 10 && var("user/active") == "true"
  ```

  支持比较（`> < >= <= == !=`）、四则算术、`&&`（且）`||`（或）`!`（非）。可视构建器会帮你拼这些，写不下去再切「高级（写表达式）」。

> **小心 ABA 转圈**：脚本 A 改了变量、触发脚本 B、B 又改变量触发 A……系统有[链式熔断](#44-脚本被熔断时budget-上限)兜底，到一定深度自动掐断，不会无限循环卡死服务器。

### 4.4 调试：试跑 + 轨迹高亮

点右上 **试跑**（⚠ 真执行），跑完积木会按执行顺序逐个亮边框，颜色含义：

| 颜色 | 含义 |
|---|---|
| 🟢 绿（执行了） | 这块正常执行到了 |
| 🟡 黄（被拦下） | 触发太频繁被预算闸拦下 / 命令被安全规则拦下 |
| 🔴 红（出错了） | 这块执行时报错（比如引用了不存在的元素 / 变量值不是数字） |

没点亮的积木 = 这次没走到（比如「如果」走了「那么」，「否则」里的就不亮）。这是排查「为什么没生效」最快的办法。

### 4.5 脚本被「熔断」时（Budget 上限）

为了不让一条写错的规则拖垮整台服务器，系统有**执行预算**三道闸。**碰到上限是保护机制，不是 bug**：

| 闸 | 默认 | 碰到会怎样 |
|---|---|---|
| 单次触发最多执行多少块 | 50 | 一次触发里积木（含循环 / 嵌套展开）超过这么多，后面的不再执行 |
| 单条规则每秒最多触发几次 | 10 | 超出的触发直接丢掉（不排队） |
| 链式深度 | 8 | 脚本改变量又触发别的脚本，连环到这么深就掐断本次 |

碰到熔断时，积木试跑会显**黄色（被拦下）**，服务器日志和审计也会记下是哪条规则在转圈。
**系统只掐断这一次、不会自动停用你的规则**——你自己去看日志、把规则改合理（比如把「重复」次数调小、把定时器间隔拉长）。

这些上限服主可在 config 里调（见 [5.3](#53-预算与采样间隔调参)），但默认值对绝大多数场景够用。

## 第五部分：服主运维

### 5.1 权限节点

脚本相关权限（定义在 `paper-plugin.yml`）：

| 节点 | 默认 | 作用 | 建议 |
|---|---|---|---|
| `canvas.script.edit` | 所有人 | 给自己能打开的墙编排积木脚本 | 想限制谁能写脚本时收紧 |
| `canvas.script.trigger.global` | 所有人 | 用「玩家进服 / 击杀 / 退服 / 右键画板」这类**全服事件**触发器 | 全服监听有放大效应，介意的服收成 op |
| `canvas.script.sound` | 所有人 | 在脚本里用「播放声音」积木 | 怕声音轰炸可收成 op |
| `canvas.script.command` | **仅管理员** | 在脚本里用「执行命令」积木（危险面） | **保持 op**，且务必配合命令模板白名单 |

> **权限在「保存规则时」检查，不在执行时**：规则是作者权限的快照——作者保存时有权限就行；
> 之后作者失去权限，旧规则照常运行（服主可手动停用该规则）。所以收权限要配合检查已有规则。

### 5.2 命令模板白名单

#### 为什么要配

「执行命令」积木能以**服务器控制台身份**跑命令——等于把服务器权限借给写脚本的玩家。
直接放开 = 灾难。所以 HikariCanvas **不内置任何命令模板**，全靠服主在 config 里手写白名单：
**没写进白名单的命令，脚本里引用了也不会执行。**

#### 怎么配

编辑 `plugins/HikariCanvas/config.yml` 的 `scripts.command-templates` 段（默认是注释掉的示例，去掉注释即可用）：

```yaml
scripts:
  command-templates:
    announce:
      command: "say [招牌] {msg}"
      params:
        msg: { max-length: 64 }
    give-reward:
      command: "give {player} diamond 1"
      params:
        player: { type: online-player }   # 只接受在线玩家名，杜绝选择器
```

- `command` 是真正执行的命令全文，`{参数名}` 是占位符，由写脚本的玩家在积木里填值。
- 每个占位符必须在 `params` 里声明。`max-length` 是单个参数值的长度上限（默认 64）。
- 玩家在「执行命令」积木里**只能选模板 + 填参数**，看不到也改不了命令原文。

#### 安全须知

- **填进来的参数值会自动剥掉换行和 `§` 颜色码。**
- **值里带 `@`（目标选择器）一律拒绝执行**，除非该参数声明了 `type: online-player`（此时值必须精确命中某个**在线玩家**的名字）——杜绝 `@a` / `@e` 这种选择器夺权。
- **参数值可以含空格**，空格会成为命令的额外参数。设计模板时把「自由文本」参数放在命令**末尾**（比如 `say` 的消息），别放在 `give` 这种按空格切参的命令中间。
- 命令以**控制台身份**执行（模板是你写的，等于你授权了这些命令）。
- 每次执行都会进**审计日志**（事件 `SCRIPT_COMMAND_EXECUTED`，含替换后的命令全文 + 来源规则），方便事后追查。

> `.canvas` 工程文件导出时**包含脚本**。导入到别的服务器时，如果某个命令模板在新服 config 里不存在，那块「执行命令」积木会**灰显 + 标红**（不可执行），规则其余部分照常可用——所以恶意工程文件搬不动你的命令。

### 5.3 预算与采样间隔调参

`config.yml` 的 `scripts` 段（改完跑 `/canvas reload` 大部分可热更，只影响后续，不裁剪已有规则）：

```yaml
scripts:
  # 单面墙可挂的脚本规则数上限（防玩家堆几百条拖慢服务器）
  max-rules-per-wall: 16
  # 单面墙元素总数上限（脚本「克隆元素」是唯一能无限堆元素的入口，达上限后克隆被拒）
  max-elements-per-wall: 200
  # 「玩家靠近 / 离开范围」触发器的采样间隔（游戏 tick，20 tick = 1 秒；默认 10 = 半秒扫一次）
  # 越小越灵敏，但主线程扫描越频繁；范围 1~200。底层固定每 2 tick 跑一次，填 1 和 2 等效。
  player-near-sample-ticks: 10
  budget:
    max-actions-per-run: 50    # 单次触发最多执行多少块动作
    max-runs-per-second: 10    # 单条规则每秒最多触发几次（超出丢弃）
    max-chain-depth: 8         # 链式熔断深度（脚本写变量又触发别的脚本）
  tween:
    max-fps: 60                # 补间动画帧率硬上限（per-wall 帧率由玩家在编辑器里调，默认 30）
    max-concurrent: 16         # 同时活跃的补间动画上限（超限新任务报错不执行）
```

> **设计哲学**（见 `PROPOSAL.md §2.1`「工具不是保姆」）：这些上限是**安全阀**，不是自动调优。
> 系统**不偷偷降帧、不自动停用规则**——数据透明地摆给你，调多少由你决定，性能够不够你自己判断。

### 5.4 故障排查

| 现象 | 可能原因 | 怎么办 |
|---|---|---|
| 「执行命令」积木**灰显** | 服主没配命令模板 / 该模板被删 / `.canvas` 导入时本服没这个模板 | 在 `config.yml` `scripts.command-templates` 配上对应模板，`/canvas reload` |
| 某触发器在积木库里**用不了 / 提示无权限** | 玩家缺对应权限（全服事件 / 声音 / 命令） | 给玩家加 `canvas.script.trigger.global` / `.sound` / `.command` |
| **规则不触发** | 规则被停用 / 帽子条件没满足 / 招牌没在游戏里部署 | 检查规则是否「已启用」；用**试跑**看积木走没走通；确认招牌确实摆在游戏里 |
| 规则**偶尔不跑 / 跑一半停** | 撞到执行预算（每秒触发次数 / 单次动作数 / 链深熔断） | 看服务器日志和审计的 `SCRIPT_RUN_BLOCKED`；把触发频率 / 循环次数调合理，或调高 `budget` 上限 |
| **试跑时它真做了事** | 试跑就是真执行（发消息 / 命令 / 改招牌都会真发生） | 这是设计如此——试跑前心里有数，别在生产高峰试跑会广播 / 发奖励的规则 |
| 改了 config 不生效 | 部分参数需重启 | `/canvas reload` 热更预算 / 采样 / 模板；改不动的重启服务器 |

审计事件（写进审计日志，便于追查谁做了什么）：
`SCRIPT_CREATE`（建规则）/ `SCRIPT_UPDATE`（改规则）/ `SCRIPT_DELETE`（删规则）/
`SCRIPT_ENABLE`（启停）/ `SCRIPT_RUN_BLOCKED`（被预算掐断）/
`SCRIPT_COMMAND_EXECUTED`（执行了命令模板，含全文）/ `SCRIPT_TEST`（试跑）。
