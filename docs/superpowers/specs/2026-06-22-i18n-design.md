# 0.8.2 i18n 设计方案

**日期**：2026-06-22
**版本**：0.8.2（计划）
**状态**：设计定稿（待实施）
**作者**：HaruHyacinth

---

## 0. 目标

把 HikariCanvas **插件本体**（不含开发文档）做成完整的双端 i18n：
- **后端**（Java 插件）：玩家在游戏内看到的全部文字按**玩家客户端语言**显示，并消除当前英/中混用的乱象。
- **前端**（Web 编辑器）：补齐已有 i18n 体系的漏网字符串 + 修 2 个翻译 bug。

起步语言：**zh_cn + en_us**。

---

## 1. 现状（实施前实测）

### 前端（Web 编辑器）—— 基础设施齐全，约 85–90% 已 i18n
- 自写 i18n：`web/src/i18n/index.ts`（`useI18n`）+ `web/src/i18n/messages.ts`（~1000+ key，27 分组），zh + en。
- locale 存 localStorage `hikari-canvas:locale`，`navigator.language` 自动检测，TopBar 一键切换，默认兜底 en。
- 后端错误走「**发码、前端查表翻译**」（`errors.*` 覆盖 50+ 错误码），前后端边界清晰。
- **漏网**（7 处硬编码 + 2 bug）：
  - `web/src/network/wsClient.ts:935` 「服务器长时间不可达…」、`:947` 「token 丢失…」、`:733` 「ready payload 缺失…」
  - `web/src/stores/scriptEdit.ts:134/162/218` 三处校验/失败提示、`:40` 默认规则名「新规则」
  - `web/src/i18n/messages.ts:1332/1349` 英文版 `topbar.switchLocale`/`moreSwitchLocale` 误填中文「切换到中文」

### 后端（Java 插件本体）—— 基本零 i18n，语言不统一
- **无任何 lang 系统**（无 messages.yml / ResourceBundle / Messages 类）。
- 约 **164 处**玩家可见硬编码文字，散在 ~10 文件。
- 语言乱：`/canvas` 命令 + ActionBar 大多**英文**（~130 处），`BenchmarkSubCommand` 压测反馈 + 脚本日志是**中文**（~11 处）。
- 未用 `Player.getLocale()`，无默认语言配置。
- 例外：`RailScheduleProvider` 硬编码 `Locale.SIMPLIFIED_CHINESE`（仅日期格式化）。

---

## 2. 固化决策（不可越界）

1. **语言来源 = 按玩家客户端语言**：`Player.getLocale()` 映射到支持的 lang；缺语言 / 无玩家上下文 → config 默认。
2. **默认兜底语言 = `en_us`**（国际 OSS 惯例 + 现命令本就英文；服主可在 config 改）。
3. **存储 = `lang/*.yml`，jar 默认 + 服主可覆盖**：jar 内置 `lang/zh_cn.yml` + `lang/en_us.yml` → 首次启动拷到 `plugins/HikariCanvas/lang/`（同字体/图标的「默认 + 服主目录覆盖」路数）；jackson-yaml 解析；`/canvas reload` 热重载。服主可改文案、加语言。
4. **控制台日志 / 审计 不进 i18n**：运维向，统一**英文**（把现有几行中文日志改英文，消除混杂）；`audit/` 事件本就是结构化 code，不翻译。
5. **WS 错误层不动**：已是「后端发 code、前端翻译」，本次不碰。后端 i18n 只覆盖**游戏端**（命令回复 / ActionBar / chat）。
6. **起步只 zh_cn + en_us**：不做 `/canvas lang` 手动覆盖（YAGNI）；服主可自行加语言文件。

## 3. 后端架构

### 3.1 新单元 `Messages`（单一职责：加载 + 解析 + 取文案）
落点建议：`plugin/src/main/java/moe/hikari/canvas/i18n/Messages.java`（新包 `i18n`）。

职责与接口：
- **加载** `load()`：扫 jar `/lang/*.yml` 作默认 → 拷缺失文件到 `plugins/HikariCanvas/lang/` → 读服主目录全部 `*.yml` → 解析进 `Map<String /*locale id*/, Map<String /*key*/, String /*MiniMessage*/>>`。`reload()` 热重载（接 `/canvas reload`）。
- **语言解析** `String localeId(CommandSender)`：
  - 玩家：`player.locale()`（Java `Locale`）→ 归一为 `language_country` 小写（如 `zh_cn` / `en_us`）→ 若有该 lang 文件用之；否则退到同语言任一变体；再否则 → 默认 `en_us`。
  - 控制台 / 非玩家：默认 locale。
- **取值** `Component get(CommandSender to, String key, TagResolver... placeholders)`：
  - 查 `localeId(to)` 的 map → 缺则查默认 locale → 再缺回退 key 字面（防崩 + 便于发现漏 key，记一次性 warn）。
  - 取到的 MiniMessage 串经 `MiniMessage.miniMessage().deserialize(raw, placeholders)` → 返回 `Component`。
- 便捷重载：`get(to, key)`（无占位符）、`send(to, key, …)`（取 + `to.sendMessage(component)`）。

设计要点：
- **占位符 = 命名 tag**：yml 写 `command.open-editor: "Open editor: <url>"`，调用 `Placeholder.unparsed("url", url)` 注入。颜色等格式服主可在 yml 内用 MiniMessage 标签自行加。
- `Messages` 持有 config 默认 locale + 服主 lang 目录引用；构造期注入，便于单测。
- 不依赖具体命令/监听器，纯 lookup + format，可独立测试。

### 3.2 调用方改造
每个发射点：
```
sender.sendMessage("No active session.");
```
→
```
messages.send(sender, "command.no-session");
```
带值：`messages.send(sender, "command.open-editor", Placeholder.unparsed("url", url));`

ActionBar：取 `Component` 后走 `player.sendActionBar(component)`。

### 3.3 key 命名 + 文件
- 分组前缀：`command.*` / `wand.*` / `frame-protect.*` / `benchmark.*` / `schedule.*`（如有玩家可见）等，按发射文件归类。
- **两份 yml（zh_cn / en_us）都补齐全部 key**——这一步顺手把英/中混用统一：现英文的命令、现中文的压测，全部进 key 体系，两语言都给全。

## 4. 前端收尾
- `wsClient.ts` 3 处硬编码网络/协议错误 → `messages.ts` `errors.*`（沿用 `localizeErrorCode` 或直接 `t`）。
- `scriptEdit.ts` 4 处校验/失败提示 + 默认规则名 → `messages.ts` `script.*`（store 内取 locale 用现有 `useUiStore().locale` + messages 表）。
- 修 `messages.ts:1332/1349` 两个 bug（英文版填正确英文）。
- 加 **zh/en key 对齐校验**（vitest）：遍历两语言 key 集合必须一致，防一边缺 key。

## 5. 控制台日志
- `script/engine/ActionExecutor.java:569/590` 等中文日志 → 改英文。
- 全局扫一遍 `logger.*` 的中文串，统一英文。**不接 i18n。**

## 6. config
- config.yml 新段：
  ```yaml
  i18n:
    default-locale: en_us   # 玩家客户端语言不支持时的兜底；服主 lang/ 目录可加语言
  ```
- `HikariCanvasConfig` 加字段 + 注入 `Messages`。`/canvas reload config` 同步默认 locale。

## 7. 测试
- **后端**：
  - `MessagesTest`：locale 解析（玩家 `zh_cn`→zh / `fr_fr`→默认）、取值 + 占位符注入、回退链（缺 key → 默认 locale → 字面）。
  - **lang 文件 key 对齐**测试：jar 内 `zh_cn.yml` 与 `en_us.yml` key 集合必须一致（防漏译）。
  - 现有 ~1500+ 后端测试回归全绿。
- **前端**：
  - zh/en `messages.ts` key 对齐 vitest。
  - 现有 vitest 回归全绿。

## 8. 不做（YAGNI）
- `/canvas lang <x>` 玩家手动覆盖语言。
- 起步多于 zh+en 的内置语言（服主可加）。
- WS 错误层后端发字面串（保持发 code）。
- 控制台日志 / audit 的多语言。
- `RailScheduleProvider` 日期格式化 locale 跟随玩家（**可选项**，低优先；本版可不做，留记）。

## 9. 受影响文件（粗估）
- **新增**：`i18n/Messages.java` + 包；jar `resources/lang/zh_cn.yml` + `en_us.yml`；`MessagesTest` + lang 对齐测试。
- **改后端**：`command/`（CanvasCommand + 各 SubCommand）、`deploy/FrameProtectionListener`、`session/WandListener`、`benchmark/BenchmarkSubCommand`、`HikariCanvas`（装配 + 拷 lang + cleanup）、`HikariCanvasConfig`（+ default-locale）、`script/engine/ActionExecutor`（日志英文化）等 ~10 文件。
- **改前端**：`wsClient.ts`、`scriptEdit.ts`、`i18n/messages.ts`、+ 对齐测试。
- **改文档**：`config.yml` 注释、`deployment.md`（lang 目录 + default-locale）、`troubleshooting.md`（语言相关）、journal、版本号 → 0.8.2-SNAPSHOT。

## 10. 验收
- 玩家用中文客户端进服 → `/canvas` 命令、wand 提示、压测反馈全中文；英文客户端 → 全英文。
- 服主改 `plugins/HikariCanvas/lang/zh_cn.yml` 某行 + `/canvas reload` → 即时生效。
- 控制台日志全英文、无中英混杂。
- 前端切 en → 网络错误 / 脚本校验提示 / 语言切换按钮全英文，无漏网中文。
- zh/en key 两端各自对齐，无缺译。
