# 0.9.8 去除 AI 味 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 1.0 正式发布前，把仓库里「AI 味过重」的内容清掉——用户可见文案里泄漏的内部阶段编号、代码注释里的开发过程标记 / 自辩护独白、契约文档正文里的过程叙事——同时**一字不动任何契约规格与代码逻辑**。

**Architecture:** 分 12 个 task。B1 用户可见文案（最高价值）→ B2-B5 代码注释（backend×2 + frontend×2，主体是「剥前缀留正文」的机械活）→ B6-B10 文档（dynamic-data 重灾区单列 + 契约文档 scrub + 总纲结构手术 + HOW-TO 轻扫）→ B11 CLAUDE.md 口癖 + ultrareview 档案归档 → B12 收尾（版本 bump + journal + push）。逐条编辑清单在 `.superpowers/ai-smell/findings-{A,B,C,D}.md`（4 个 opus 探索代理已产出），是每个 task 的输入源。

**Tech Stack:** Java 21（Paper 插件后端）+ Vue 3 / TypeScript（编辑器前端）+ Markdown（docs）。测试：`./gradlew :plugin:test`（后端 2151）+ `cd web && npm run test`（前端 1446 / vitest）。

## Global Constraints

**这些约束是每个 task 的隐含前置，无一例外：**

1. **零逻辑改动。** 只允许改三类内容：① 代码注释（`//` `/* */` Javadoc `<!-- -->`）；② 用户可见文案字符串的 value（i18n messages.ts 的 value、lang/*.yml 的 value、面向用户的错误串）；③ `docs/*.md` 正文。**禁止改任何可执行代码、控制流、常量数值、函数签名、i18n 的 key 名。** 若某处「不改逻辑就没法去味」→ 不改，在 report 里记下留作者。
2. **不碰 `README.md`（作者亲自维护）、`docs/journal.md`（仅 B12 追加一条会话摘要）。**
3. **剥前缀、不删正文（主操作）。** 删开头的开发阶段编号 token（`M16` / `P3` / `T1` / `0.4.3-P2` / `D10` / `K11` / decision-ID / commit hash / 拍板日期），保留后面真实正文。示例：`// M16 P2.5: 跨世界绑定会炸，必须校验 world 一致` → `// 跨世界绑定会炸，必须校验 world 一致`；标题 `### 6.5 元素级 opacity（M8 协议 v2 引入）` → `### 6.5 元素级 opacity`。**整条删只限 findings 明确标「删」的纯历史 / 墓碑 / 复述注释。**
4. **保留清单（这些不是 AI 味，删了是损失）：**
   - 非显然警告：删了会踩坑的并发 / 顺序 / NPE / 主线程 / 浏览器 gotcha
   - 装配 / 初始化顺序依赖
   - 契约 `§` 交叉引用（文档间导航）
   - **契约规格本体**：协议 wire 格式、DB schema / DDL / migration、渲染数学 / pseudocode、模板 YAML 规格、安全威胁模型、权限节点表、审计事件表、config 默认值
   - 合法命令名 + 领域术语（即使含数字，如某 admin 子命令）
   - **用户文档里「功能自 X 版起可用」的版本标签**（对读者有意义）。判据：`0.4.3 起可用` = 保留；`0.4.3-P2 的 VariableStore 重构` = 删内部阶段号
5. **每个代码 task 结束的验证闸：** 全量 `./gradlew :plugin:test`（后端 2151 全绿）/ `cd web && npm run test`（前端 1446 全绿），**测试数一个不变**（注释 / 文案改动不影响编译，测试数变化 = 误伤了逻辑）。docs task：`git diff --stat` 只含 `.md`，并对该文档 grep 关键规格锚点（op 名 / DDL 关键字 / 数学符号）确认未减行。
6. **findings 行号是探索时的快照；前序 task 改动会让行号漂移。** 一律**按 findings 里引用的注释 / 文案原文内容定位**，不按行号盲改。
7. **提交纪律：** 每个 task 只 `git add` 自己碰的文件，**禁 `git add -A`**（`findings.md` / `progress.md` / `task_plan.md` / `.superpowers/` scratch 不得扫入）。SSH 签名。**本地累积提交，B12 统一 `git push origin main` + 逐 commit 验签**（照 0.9.6 / 0.9.7 惯例）。身份 `HaruHyacinth <122684177+HyacinthHaru@users.noreply.github.com>`，禁 Claude 署名。
