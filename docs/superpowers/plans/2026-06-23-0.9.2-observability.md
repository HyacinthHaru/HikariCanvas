# 0.9.2 可观测性 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 给服主自助诊断能力——把现有 `/canvas stats` 增强成完整健康视图（地图池分世界/变量/动画占用），并新增 `/canvas diagnose <wallId>` 只读诊断链（逐环节报"某块墙为什么渲不出"）。

**Architecture:** 现有 `stats` 在 `CanvasCommand.runStats`，但 CanvasCommand 没有 VariableStore/AnimationTicker/TweenScheduler 依赖。新建 `DiagnosticsSubCommand`（照 `VariableSubCommand`/`BenchmarkSubCommand` 范式：构造注入各子系统 + 纯逻辑方法 + 在 `CanvasCommand.build()` 接线），把增强后的 `stats` 与新 `diagnose` 都放它里面。各子系统补**只读 accessor**（多数已有 getter，少数新增）。命令在主线程跑——MapPool 读（synchronized + assertMainThread）安全。**只读观测，不做任何修复动作**（cleanup stub 不碰；符合"工具不是保姆"——数据透明不替服主决策）。

**Tech Stack:** Java 21 / Paper Brigadier / Adventure MiniMessage / JUnit 5。i18n 走 `Messages` + lang `command.*`。纯后端，无前端、无协议、无 schema 改动。

## Global Constraints

- **权限**：`stats` + `diagnose` 都用现有 `canvas.admin`（default op），不新增权限节点。
- **i18n**：所有输出走 `messages.send(sender, "command.<key>", Placeholder.unparsed(...))`；新 key 必须 zh_cn + en_us 各一份（`LangFileParityTest` 自动兜漏译）；en 值英文 / zh 值中文；带 MiniMessage 颜色标签沿用现有 `command.stats` 风格。
- **只读**：本版只暴露数据，不删不改不修复；`cleanup` stub 原样不动。
- **线程**：命令在主线程执行；MapPool 的读 accessor 主线程安全（synchronized）；SessionManager/VariableStore/AnimationTicker/TweenScheduler 的读走 ConcurrentHashMap 无锁。新增 accessor 不得在持有 SessionManager writeLock 时碰 Bukkit API。
- **不动迁移脚本 / 不 bump 版本**直到收尾 task（Task 3）。注释中文按周边风格。
- **git**：每 task 独立 commit，SSH 签名，**禁止 `git add -A`**（工作区有未跟踪 scratch findings.md/progress.md/task_plan.md + plan 文件，绝不扫入）；只 add 本 task 文件；只 commit 不 push（最后 controller 统一）。
- **测试纪律**：改动后跑全量 `./gradlew :plugin:test`（不只单类）。

**Interfaces:**

- `SessionManager.isWallActive(String wallId) -> boolean`（或等价：该 wall 是否有活跃编辑 session；读 byWall CHM 无锁。若已有等价方法直接用，报告说明）。

- [ ] **Step 1: 补 SessionManager per-wall accessor（若无现成）**

读 `SessionManager.java`（byWall CHM ~79-81、size 1145）。若没有"给 wallId 判断是否有活跃 session"的方法，加 `public boolean isWallActive(String wallId)`（或返回 sessionId 的 `Optional`）。注意 byWall 的 key 类型（WallKey vs wallId）——按真实结构实现，无锁读 CHM。

- [ ] **Step 2: runDiagnose 诊断链**

`DiagnosticsSubCommand.runDiagnose(CommandContext)`：取 `wallId` 参数，逐环节查 + 发对应 lang 行（每环节 OK/WARN/ERROR）：
1. **墙存在**：`wallRepo.loadById(wallId)` 为空 → ERROR `not-found`，停。
2. **地图分配**：wall.mapIds() 空 / 数量与 width×height 不符 → WARN `maps-missing`（附 `MapPool.stats()` 概况）。
3. **世界加载**：`Bukkit.getWorld(wall 的 world 名)` 为 null → ERROR `world-unloaded`。
4. **活跃 session**：`sessionManager.isWallActive(wallId)` → INFO（有=编辑中 / 无=无人编辑，后端待渲、缺前端驱动——非错误）。
5. **ProjectState 解析**：尝试解析 wall 的 project_json（loadById 已带 state 或单独解析）→ 失败 ERROR `state-corrupt`。
6. **动画态**：`AnimationTicker.isWallAnimating(wallId)` → INFO（在播时间轴 / 静态）。
7. **总结**：全 OK → `ok`；否则汇总首个 ERROR/WARN。
各环节文案走 `command.diagnose.*` lang key（占位符填 wallId / world / 数量等）。**只读，不触发任何修复。**

- [ ] **Step 3: lang `command.diagnose.*`（zh + en）**

新增一组 key：`header`（`诊断 <wall_id>：`）/ `not-found` / `maps-ok` / `maps-missing` / `world-loaded` / `world-unloaded` / `session-active` / `session-none` / `state-ok` / `state-corrupt` / `anim-playing` / `anim-static` / `summary-ok` / `summary-issues`。OK 行用 `<green>`、WARN `<yellow>`、ERROR `<red>`、INFO `<gray>`，header `<gold>`。占位符按需。

`DiagnosticsSubCommand.suggestWallIds`：照 `VariableSubCommand.suggestWallIds`（588-594）范式，从 `wallRepo` 列 wallId 补全（用 `wallRepo` 的列举方法；若无 allWallIds 则加一个或用现有列举）。
