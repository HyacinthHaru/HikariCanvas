# 0.7.0-P2 脚本执行引擎 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 落地脚本执行引擎——P2 账单清欠 + ConditionEvaluator(扩 expr)+ ScriptRunner(Budget/ABA 熔断)+ ActionExecutor(8 动作)+ TriggerRouter(变量/定时/墙就绪 3 触发器)+ 装配;**MVP 闸**:浏览器 console 以 JSON 建规则,游戏内生效。

**Architecture:** 新包 `moe.hikari.canvas.script.engine`。TriggerRouter 监听 VariableStore ChangeListener(O(1) 投递)/ 自持 SES 调度 timer / wallReady 由启动恢复与部署完成点回调;ScriptRunner = `newSingleThreadScheduledExecutor`(单线程串行 + wait 用 schedule 续接);ABA 链深用 **runner 线程 ThreadLocal**(setValue 的 fireChange 同步发生在 runner 线程,Router listener 读 ThreadLocal 得 depth+1——零 VariableStore API 改动);ActionExecutor 主线程 hop 走 `Bukkit.getScheduler().runTask`,setElementProperty 双路径(有 session 走 EditSession 标准 op / 无 session headless WallRepo+ticker)。条件求值扩 `template/expr`(单一文法,数字语义走 StrictNumber)。

**执行纪律:** 同 P1(SSH 签名/禁 Claude 署名/每 commit push/journal 收口统一写)。测试 `./gradlew :plugin:test`(基线 1378)/ `cd web && npm run test`(529,本期前端预计零改动)。

## 关键决策(计划期锁死,实施不再议)

| # | 决策 | 理由 |
|---|---|---|
| K1 | **ABA 链深 = runner ThreadLocal**:Runner 执行 setVariable 前置 `CHAIN_DEPTH.set(ctx.depth)`,finally 清;VariableStore.fireChange 同步在调用线程跑 → Router listener 读 ThreadLocal,投递下游 run 时 depth+1;≥ max-chain-depth 掐断 + audit | 不改 VariableStore API(source 字段已被 bind 占用);同步 fireChange 保证线程归属 |
| K2 | **条件文法扩在 `template/expr` 原地**:加 `< <= > >=`、`+ - * /`、`var("fullName")` 函数节点;优先级 `! > */ > +- > 比较 > ==!= > && > \|\|`;数字比较/算术的 string→number 走 `StrictNumber.parse` | 单一文法权威;模板 visible_when 得到超集无破坏;条件是后端独有(D5),无前端镜像负担 |
| K3 | **var() 解析 = 注入 resolver**:Evaluator 加可选 `Function<String,String> varResolver`(null 时 var() 求值报错);脚本侧 resolver = VariableStore cached 值 + `VariableInterpolator.resolveFullName(raw, wallId)` 注入 wall 上下文;miss → null(truthy=false) | 模板路径不受影响(不传 resolver) |
| K4 | **runCommand P2 = blocked no-op**:执行到该动作记 step `blocked(命令模板系统 0.7.0-P3)` + FINE log,链继续 | 命令模板系统按分期属 P3 |
| K5 | **RUN_BLOCKED audit 限频**:per-rule 10s 窗口内只记 1 条(内存时间戳),掐断照常只是不刷 audit 表 | 10 runs/s 限流被持续触发时不能把 audit DB 打爆 |
| K6 | **timer 不搭 VariableProviderDaemon**:Router 自持 runner 的 SES 调度(`scheduleAtFixedRate` → 投递 run);规则删除/禁用/墙删时 cancel | 语义不同(事件驱动 vs 周期 refresh);单线程串行天然防重入 |
| K7 | **ScriptStore 监听粒度 = wall 级**:`interface Listener { void onWallScriptsChanged(String wallId); }`,任何 create/update/delete/enable/clearWall/loadFromDb 后通知;Router 收到即整墙 rebuild(≤16 规则,O(墙)便宜) | 比 per-rule 增量简单一个量级,正确性免证 |
| K8 | **小数截断收紧**:dispatcher 数值字段(intervalSeconds/rangeBlocks/ms/seekMs)非整数值(如 1.9)→ INVALID_PAYLOAD(批次3 #7 同理"显式给了但类型错应拒") | 双端语义零漂移 |
| K9 | **wallReady 两个触发点**:① 启动 `WallRestorer.restore()` + `ticker.autoRegisterAll` 之后对全部恢复成功的墙各发一次 ② `SessionManager.confirm`(部署完成)后对该墙发一次;**编辑器 persistWall 不算**(那是改稿不是就绪) | 语义贴"墙加载完成(开机/部署)" |
| K10 | **trace 基建现在埋**:ScriptRunner 每 run 产 `List<TraceStep>(blockId,kind,result,detail)`,P2 只进 FINE log + log action 消费;P3 接 script.test ack | P3 终审账单要求 seam 异步化,trace 结构先就位省返工 |

## 任务分解(3 批次 + 收口)

### 批次 1 — T1 账单清欠 + T2 条件求值(2 commit)

**T1(P1 终审账单,scripting.md §11)**:
- `ScriptStore`:加 `snapshotAll(): Map<String,List<ScriptRule>>`(不可变快照)+ `addListener(Listener)`(K7;通知在 compute 外、状态已落定后,异常隔离 try-catch)+ `update` 缺 enabled 时**继承现值**——实现方式:`ScriptOpDispatcher.parseIncomingRule` 加第 3 参 `Boolean enabledFallback`(update 路径传现有 rule.enabled(),create 传 true);LogicTest 补 case
- K8 小数收紧:dispatcher 数值字段整数性校验 + LogicTest case
- 权限拒绝路径 dispatch 级测试:MockBukkit 在线玩家 deny case(checkBasePermission 在线收回真拒 / checkFacets 缺面拒 + PERMISSION_DENIED audit)。装配照项目 MockBukkit 既有用法(grep `MockBukkit` 找先例);若 MockBukkit 与 MainThreadPerms.callSyncMethod 不兼容则改为对 `MainThreadPerms.resolve` 抽 seam 注入 fake——二选一,实施者验证后定,**不许跳过**
- Commit:`0.7.0-P2-1: P1 终审账单清欠(Store 暴露面/enabled 继承/权限拒绝测试/整数收紧)`

**T2(ConditionEvaluator)**:
- `template/expr/ExpressionParser`:文法扩 K2(注意现有 `equ` 层拆成 `cmp` 与 `equ` 两层;`primary` 加 `var "(" string ")"` 函数形态,AST 加 `Expr.VarRef(String fullName)`);现有 4 个节点语义不动
- `ExpressionEvaluator`:加算术/比较求值(数字语义:两侧任一可解析为数字则按 StrictNumber.parse 数值比较,否则字符串比较;算术恒数值;除零 → 0.0 并 FINE log,不抛)+ `VarRef` 走注入的 resolver(K3)
- 新 `script/engine/ConditionEvaluator`:包装 parse+eval+resolver 注入 + parse 结果缓存(per-rule condition 字符串 → Expr,ConcurrentHashMap,规则更新时由 Router rebuild 自然换 key);**parse 失败 → 条件视为 false + WARNING 一次**(不让坏条件炸链)
- 测试:Parser 新文法 ≥12 case(优先级/括号/负数/var()/畸形拒绝)+ Evaluator 数字语义 ≥10 case(含 "10" vs 9 数值比较、字符串 fallback、除零、var miss)+ ConditionEvaluator 缓存/坏条件 case;**template visible_when 既有测试必须全绿(回归红线)**
- Commit:`0.7.0-P2-2: 条件文法扩展(比较/算术/var())+ ConditionEvaluator`

### 批次 2 — T3 Runner + T4 ActionExecutor(2 commit)

**T3(ScriptRunner + Budget)**:
- `script/engine/ScriptRunner`:`newSingleThreadScheduledExecutor(daemon)`;`submit(RunRequest(wallId, rule, TriggerContext))`,`TriggerContext(source: VARIABLE/TIMER/WALL_READY/TEST, chainDepth, triggerDetail)`;执行 = 逐 action 走 ActionExecutor + If 走 ConditionEvaluator 递归;`wait` → 剩余动作包成 continuation `schedule(delay)`(深度计数已由 P1 validator 限 3);trace(K10);幂等 `shutdown()`
- `script/engine/ScriptBudget`:config `scripts.budget` 段(`max-actions-per-run:50 / max-runs-per-second:10 / max-chain-depth:8`;max-delay-* 已是 validator 静态项,不重复)+ HikariCanvasConfig.ScriptsConfig 扩字段(照 ScheduleConfig 嵌套 parse 范式,/canvas reload 热更照 P1 maxRulesPerWall 先例)+ per-rule 固定窗 runs/s 计数(clock 注入 seam)+ chainDepth ≥ max 掐断 + actions 计数超掐断;掐断 → audit `SCRIPT_RUN_BLOCKED(reason=rate|chain|actions)`(K5 限频)+ trace step blocked
- K1 ThreadLocal:`static final ThreadLocal<Integer> CHAIN_DEPTH`(包级,Router 读)
- 测试(纯 fake,clock 注入):runs/s 窗口边界 / chain 掐断 / actions 超限 / wait 续接(用 SES 直跑或可注入 executor 同步化)/ trace 形态 / audit 限频
- Commit:`0.7.0-P2-3: ScriptRunner 单线程执行管线 + Budget 三闸 + ABA 链深`

**T4(ActionExecutor)**:
- `script/engine/ActionExecutor`:依赖注入 record/构造(VariableStore / AnimationTicker / SessionManager / WallRepo / Plugin(可 null 测试)/ Logger / VariableInterpolator 所需件)。逐动作:
  - setVariable:value 先过占位符插值(查 `VariableInterpolator` 现有字符串插值 API 复用;无合适 API 则只做 `${var:X}` 简单替换,与 Compositor 同 regex)→ `store.setValue(resolveFullName(fullName, wallId), value, null)`(K1 ThreadLocal 已由 Runner 置好)
  - incrementVariable:读 cached 当前值 `StrictNumber.parse` + delta → setValue(格式:整数值无小数点,否则去尾零;单线程串行无内部 race)
  - setElementProperty:`ElementPropertyApplier`(独立类)双路径——有活跃 session:定位 EditSession,**复用 EditOpDispatcher case "element.update" 所调的同一 EditSession 方法**(实施时读 dispatcher 找准方法名),成功后照 dispatcher 收尾链推 patch + throttler 脏区;无 session:WallRepo 读 state → 改 element(immutable 重建,value 按 property 类型转换:数值属性 StrictNumber/text·fill 字符串,fill 仅收 `#RRGGBB(AA)` 转 SolidFill)→ `wallRepo.updateState` → `ticker.isWallAnimating ? invalidate : refreshAutoPlay`(照 SessionManager.persistWall L669-688 链);elementId 不存在 → step error 不断链
  - playTimeline:ticker.play/pause/seek 直调(线程安全);Result 失败 → step error
  - playSound:主线程 runTask;wall 位置从 WallRepo.Wall 取(实施时确认字段);scope near = 墙世界内距墙原点 ≤16 格的玩家,all = 全服在线;soundId 非法(Registry 查无)→ step error 不抛
  - wait:由 Runner 处理(executor 不见)
  - runCommand:K4 blocked
  - log:插值后 `logger.info("[脚本] " + msg)`(不进 audit——P1 已记 SCRIPT_* 管理事件,log action 是玩家级高频,进 audit 会刷库;**此处与 scripting.md §2.3 "入 plugin logger + audit"偏差,收口时改契约该行**)
  - 全动作三层异常隔离:单 action throw → step error + WARNING log + 继续下一动作
- 测试:每动作一组(fake store/ticker/repo;主线程 hop 在 plugin=null 时直跑——照 MainThreadPerms 测试装配惯例);setElementProperty headless 路径全链(真 WallRepo tmpdir SQLite + fake ticker 断言 invalidate/refresh 调用);value 类型转换边界
- Commit:`0.7.0-P2-4: ActionExecutor 8 动作(双路径 setElementProperty / 主线程 hop / 三层隔离)`

### 批次 3 — T5 TriggerRouter + 装配 + MVP(1-2 commit)

**T5**:
- `script/engine/TriggerRouter`:索引 `Map<String fullName, Set<(wallId, ruleId)>>`(variableChange,resolveFullName 同 TimelineTriggerRegistry 范式)+ `Map<ruleKey, ScheduledFuture>`(timer)+ wallReady 直查 snapshot;`rebuildWall(wallId)`(ScriptStore.Listener 接入,K7)/ `rebuildAll()`;`onVariableChange(event)`(VariableStore listener:VALUE_SET/UPDATED/CREATED → 查索引 → 对每条 enabled 规则 `runner.submit(depth = CHAIN_DEPTH.get()+1 或 0)`)/ `fireWallReady(wallId)`;**disabled 规则不进索引**;timer 重建 = cancel 旧 + schedule 新

- **MVP 集成测试**(`script/engine/EndToEndScriptTest`,照 EndToEndSmokeTest 风格全 fake 装配链):① 变量变化 → 条件真 → setVariable + playTimeline(fake ticker 断言)② 条件假 → 不执行 ③ ABA:规则 A 写 x 触发规则 B 写 y 触发 A……链深掐断 + audit ④ timer 触发(注入 clock/手动 tick)⑤ disabled 规则不触发 ⑥ wallReady 触发
- Commit:`0.7.0-P2-5: TriggerRouter 3 触发器 + 全链装配 + MVP 集成测试`
