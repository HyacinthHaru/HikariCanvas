## A · 左工具栏自动两栏(问题一)
**现状**:`web/src/components/layout/LeftTools.vue` 15 个工具纵向单列 `w-12`(48px),无 `overflow-y`,窗口**矮**时底部按钮(Undo/Redo)被截出视口,无折叠无滚动。
**方案(用户定)**:自动两栏。
**改法**:`useWindowSize`/`useResizeObserver`(@vueuse/core)监听可用高度,高度 < 阈值(如内容放不下)时给 `<aside>` 切两栏布局(`grid grid-cols-2` 或 `flex-wrap` + 宽 `w-12`→`w-24`);分隔线 `<div h-px>` 跨两栏需 `col-span-2`/`w-full`;tooltip 方向(右弹)在两栏时不被遮挡(必要时改 bottom)。极矮(两栏还放不下)可补 `overflow-y:auto` 兜底。两栏是自动的,不需持久化 UI 状态。

## B · 右上角更多菜单(问题二)
**现状**:`web/src/components/layout/TopBar.vue` 右侧约 14 按钮(PanelLeft/Right、Terminal、Bookmark、SnapSettings、Variable、Train、TrainTrack、Film、Puzzle、Help、Languages、主题、ThemeSwitcher),`flex justify-between` 无响应式,窗口窄时右侧按钮**静默消失**(被挤出 header 边界)。
**方案(用户定)**:更多菜单——空间够全展开;不够时把**低频**按钮收进一个 `…`(MoreHorizontal)弹出菜单。
**改法**:`useResizeObserver` 测 header 右侧可用宽,不够时把低频按钮移进 overflow popover。**高频常显**(面板切换 PanelLeft/Right、时间轴 Film、积木脚本 Puzzle、变量 Variable);**低频可收**(语言 Languages、主题 Sun/Moon + ThemeSwitcher、帮助 Help、存模板 Bookmark、对齐设置 SnapSettings、日志 Terminal)。可参照项目已有 popover 模式(SnapSettingsPopover)写一个 OverflowMenu。

## C · 画布鼠标左右拖(问题三)
**现状**:画布是原生 `overflow:auto` 容器(`.hc-canvas-padding` 1024px 撑虚空)+ wheel 劫持(只 `Ctrl+滚轮`缩放)。`usePanScroll.ts` 的 `onWheel` 非 Ctrl 时直接 return → 浏览器默认 wheel 只动 `scrollTop`;鼠标滚轮无 `deltaX` 故只上下;触控板有 `deltaX` 所以能左右。中键拖 / `Space` 拖 / `H` hand 工具**都已实现**但用户不知道。
**方案(用户定隐含)**:`Shift+滚轮`→水平(PS/Figma 标准)+ 角落加快捷键提示。
**改法**:`usePanScroll.ts` `onWheel` 在 Ctrl 分支后加 `if(e.shiftKey){ e.preventDefault(); outer.scrollLeft += e.deltaY; return; }`(把鼠标 deltaY 映射到水平)。在画布角落(ZoomBar 旁)加一行小字提示「`Shift`+滚轮横向 · 中键/`Space`/`H` 拖拽画布」。先读 `usePanScroll.ts` 确认 onWheel/onMouseDown 结构 + 找 ZoomBar/缩放条组件加提示。

## D · 变量系统四+五+六(同根因 + picker 列)
**根因(评估已查实)**:`RailScheduleProvider.DAEMON_KEY="schedule_rail"`(daemon 内部 key,为避免和 ManualSchedule 的 `"schedule"` 在 `VariableProviderDaemon` map 里 `putIfAbsent` 冲突,RailSchedule 的 `namespace()` 返回 `"schedule_rail"`)。但 `VariableMetadataHandler.buildJson` 把 `p.namespace()`(= `schedule_rail`)当成变量 namespace 下发给前端。**真实变量却是 `schedule:<wallId>/next_cars`**(RailScheduleProvider 用 `store.create("schedule:"+wallId, ...)` 写入)。→ picker 显示一堆 `schedule_rail/*` 幽灵变量(store 无对应,currentValue=null,问题四"一堆没值");选了插入 `${var:schedule_rail/next_cars}`,interpolator `resolveFullName` 不识别 `schedule_rail` 前缀 → 原样 `store.get("schedule_rail/next_cars")` miss → 报"已删除"(问题五),必须手写 `schedule:<wallId>/next_cars` 才命中。

**修法:**
1. **四+五(同根因)**:让 metadata 用**真实 store namespace** 暴露 rail 变量,使 picker 生成的变量能被 interpolator 正确 resolve(注入 wallId)。
   - 给 `RailScheduleProvider` 加方法返回 store namespace 前缀 `"schedule"`(与 ManualSchedule 同),`VariableMetadataHandler.buildJson` 用它替代 daemon key 生成 metadata 的 namespace 字段。这样 rail 的 14 个 key 与 manual 的 key 同归 `schedule` 组,picker 选中后以能注入 wallId 的形态(评估:`interpolator.resolveFullName` 对 `schedule.X` / `schedule/X` 注入 → `schedule:<wallId>/X`)引用 → resolve 命中。
   - **确认 interpolator 对 schedule 形态的注入逻辑**(评估提到 `schedule.` 前缀注入 wallId),让 rail key 走同款形态。
   - **问题四描述区分**:rail 专属 key(next_run_number/next_cars/next_service_type 等)的 `description` 加 `[铁路网络]` 前缀;manual 与 rail 共用的基础 key(next_departure 等)保持。让用户在描述层分清「手填时刻表」vs「铁路网络」来源。
2. **六 picker 列布局**:`web/src/components/variables/VariablePicker.vue` —— `.hc-vp-table` 改 `table-layout: fixed`(让列宽 28/22/44/6% 严格生效);`.hc-vp-table-wrap` 加 `overflow-x: auto`(外层 `overflow:hidden` 改 `overflow:visible` 或让 wrap 能横滚);`.hc-vp-name-cell` 去掉 `display:flex`(它让 td 脱离表格布局致列宽乱),改 td 自然块级 + 内部 `inline-flex` 包 meta。配合四/五消除幽灵变量,空值行大减。

**文件**:`plugin/.../web/VariableMetadataHandler.java`、`plugin/.../variable/provider/RailScheduleProvider.java`、`web/src/variable/interpolator.ts`、`web/src/variable/pickerLogic.ts`、`web/src/components/variables/VariablePicker.vue`、`web/src/types/variable.ts`(如需)。
