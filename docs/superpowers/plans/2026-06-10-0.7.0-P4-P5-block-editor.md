# 0.7.0 P4+P5 积木编辑器(引擎层 + 内容层)实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development。分波次,引擎层(P4)串行依赖紧、内容层(P5)部分可并行。每子任务自包含交付物 + 测试 + commit。

**Goal:** 自写 Scratch 风格积木画布,把 0.7 脚本规则从"console JSON"升级为可视化编辑。引擎层(无限画布/拖拽/吸附/嵌套/序列化)+ 内容层(6 触发器 + 8 动作 + 条件构建器 + 下拉集成 + 试跑高亮 + validator 镜像)。**P5 末 = 完整用户实测闸**。

**Architecture:** DOM+CSS(非 Konva——积木是表单密集体);`web/src/script/` 新目录,引擎独立 chunk。后端唯一执行权威不变(D5),前端纯 UI + 序列化 ScriptRule。

**约束(全程):** 我(主控)无法本地运行编辑器,只有 vitest + vite build + @vue/test-utils 组件 smoke。故:**纯逻辑(树操作/吸附几何/序列化/条件↔串/validator 镜像)重点 vitest;组件 smoke 抓崩溃;vite build 抓类型**。视觉细节留用户 P5 末实测。Git/签名纪律同 P1-P3。基线:后端 1575 / 前端 536。

## 波次 1(并行 3 个,文件不重叠)

### 任务 A — 引擎纯逻辑(blockTree / serialize / dropTarget)
**Files:** `web/src/script/model/{blockTree,serialize,dropTarget}.ts` + `__tests__`。**不动共享文件。**

- `blockTree.ts`:把 `ScriptAction[]` 视为可寻址树。path = `"actions/2/then/1"` 风格(与后端 trace blockId 同构)。导出:
  - `parsePath(blockId): string[]` / `getAt(actions, path)` / `insertAt(actions, parentPath, index, node)` / `removeAt(actions, path)` / `moveNode(actions, fromPath, toParentPath, toIndex)`(纯函数,immutable 返回新树)
  - `walk(actions, visitor)`(前序,带 path);`countBlocks(actions)`(含 if 自身,镜像后端 MAX_TOTAL_BLOCKS 计数)/ `ifDepth(actions)`
  - if 的子序列 path 段:`then` / `else`(与后端 wire 字段名一致)
- `serialize.ts`:
  - `blockLayout` 编解码:`parseBlockLayout(json): {stacks: Record<ruleId,{x,y}>}`(坏 JSON → 空)、`stringifyBlockLayout(layout)`、`autoLayout(ruleIds, existing): layout`(给缺坐标的规则纵向排布,间距 ~320px)
  - 编辑模型就用 ScriptRule 本身 + blockLayout 解析(不另造模型),此文件只管 layout
- `dropTarget.ts`:纯几何。输入 = 各积木堆/序列/插槽的屏幕矩形快照(`SlotRect{ stackRuleId, parentPath, index, x, y, w, h }[]` — 由 BlockCanvas 测量后传入)+ 拖动块的连接点坐标。输出 = 命中的 SlotRect | null(最近且在阈值内,优先垂直方向接近的序列间隙)。导出 `findDropTarget(slots, pointerX, pointerY, threshold): SlotRect|null`。**纯逻辑全测**。
- 测试:blockTree 树操作 path 解析/增删移/计数/深度 ≥15 case;serialize layout 编解码/坏 JSON/autoLayout ≥6;dropTarget 命中/阈值/最近优先/空 ≥8。
- Commit:`0.7.0-P4-A: 积木引擎纯逻辑(blockTree 树操作 / blockLayout 序列化 / dropTarget 吸附几何)`

## 波次 2(串行,依赖波次 1)

### 任务 C — 积木渲染(blockDefs + BlockStack/BlockNode)
**依赖 A(blockTree)+ B(画布)。** Files: `web/src/script/model/blockDefs.ts` + `canvas/{BlockStack,BlockNode}.vue` + BlockCanvas 接真渲染。

- `blockDefs.ts`:声明式定义每种积木 — `{ kind, category('trigger'|'action'|'control'), color(ctp 变量名), label(i18n key), fields: FieldDef[] }`。FieldDef = `{ name, type('number'|'text'|'select'|'variable'|'timeline'|'element'|'sound'|'command'|'scope'|'op'|'condition'|'statements'), label, ... }`。6 trigger + 8 action + if。**字段顺序 = 积木内表单顺序**;`if` 有 `condition` 字段 + `then`/`else` 两个 `statements` 字段。category→颜色:trigger=peach / action=blue / control(if)=green / 危险(runCommand)=red / 时间轴(playTimeline)=mauve。
- `BlockNode.vue`:递归。渲染一个 action/if 块:头部 label + 参数槽(C 阶段参数槽先渲染**占位**:显字段名 + 原始值文本,真表单留 F);if 块 C 形,then/else 用 `<BlockNode>` 递归子序列(空槽显占位)。块按 category 着色。块根 `data-block-path` 属性(供 D 测量 + H 高亮)。
- `BlockStack.vue`:trigger 帽子(读 def 渲染)+ actions 序列(map BlockNode)。`position:absolute` 读 blockLayout 坐标。
- `BlockCanvas.vue`:把假堆换成 `v-for` over `scripts.listSorted` → BlockStack(坐标来自 parseBlockLayout)。
- 测试:blockDefs 完整性(每 kind 有 def + 字段覆盖 wire 全字段) ;BlockStack/BlockNode smoke(渲染各类积木不崩 + if 嵌套渲染 + data-block-path 正确)。
- Commit:`0.7.0-P4-C: 积木渲染(blockDefs 声明式定义 + BlockStack/BlockNode 递归 + 真规则上画布)`
